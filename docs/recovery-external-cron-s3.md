# 無アクセス時の外部Cron・起動漏れ・停止再開試験

対象は`codex/recovery-operator-plan`の専用環境。共通部品の変更とは独立し、固定候補ZIP `34315c718ac34a970f64dcc5353c1208ec3b40c272be803bdfae127217200d43`の製品コードをそのまま使う。

**2026-10-19、run `aa004f79632e`でPHP方式に合格。** HTTPサーバーなし・サイトへのアクセス0で実crondが5回起動し、WordPressのCron callbackを42回観測した（42は受入チェック件数ではない）。未起動と処理途中停止による起動漏れ2枠を記録し、同一セットの再開・完了後の再起動保持を確認した。8オブジェクト、計25,074 bytesを新規取得し、サイズ・SHA-256・manifestが一致した。製品src/vendor 3,884ファイルは元ZIPおよび実行前後で一致。ワーカー・起動ログにエラー出力はなかった。

WordPress 7.0 / PHP 8.3 / MariaDB 11.8。[検証集計](recovery-external-cron-s3-validation.json)に予定枠・観測時刻・実起動時刻・保存資産を記録する。元ログ・snapshot・取得データ・コードハッシュはローカル`release-readiness/external-cron-s3/`。今回もVersion IDはnull、暗号化応答はAES256で、固定版保持の受入とはしない。

## 起動方式

PHP方式の生成DB/mediaを対象に、既存EC2上の使い捨てコンテナでBusyBox `crond`を実行する。ホストのcrontab・systemd設定は変更しない。HTTPサーバーは起動せず、サイトへのリクエスト数は0。`DISABLE_WP_CRON=true`でアクセス起点の起動を止め、外部CronがCLIで`/site/wp-cron.php`を実行する。

Cronは実時間の毎分境界で起動する。検証を短時間で進めるため、起動から45秒以内は2秒間隔でWordPressのCron入口を繰り返し呼ぶ試験用pulseを使用する。実行中の1回は終了を待つため、45秒は強制終了期限ではない。pulseは`flock -n`で同時起動を抑止する。製品handlerを直接呼ばない。WordPress側も試験用の2秒イベントを明示登録する。本番の日次設定や一般向け導入機能として配布する設定ではない。

`crond`はコンテナ内でユーザーを切り替えるためrootで動くが、WordPressワーカーは専用ディレクトリ所有者と同じ非root UIDで実行する。本番サイト・DB・秘密鍵はmountしない。AWS通信は既存EC2の認証チェーン、保存先は既存試験バケット内の新規prefixを使う。

## 検証する動作

1. 最初の予定起動枠ではCronを起動せず、実際の分境界から5秒後に起動記録がないことを検出する。Collector未作成を確認し、成功として補完しない。
2. `crond`を起動し、HTTPアクセスなしでWordPressの実PipelineがS3へDBを保存することを確認する。
3. DB保存が応答済みの位置で試験用gateを置き、Cron/workerコンテナを強制停止する。次の予定枠の起動漏れを別プロセスの試験制御から検出する。Collectorとworkspaceの内容が変わらず、未完了を成功扱いしないことを確認する。
4. 新しいCronコンテナを起動する。台帳・時刻・Cron lockを修正せず、実際の予定起動から同一intent/set IDで処理が再開し、完了することを確認する。SQL/gzipのハッシュも保持する。
5. 完了後にCronコンテナを再起動し、次の実予定枠で`already_complete`となり、完了台帳・workspaceが変わらないことを確認する。
6. 保存元DBを破棄し、S3の8資産を新しい取得領域へ読み出して、サイズ・ハッシュ・manifestの一致を確認する。

起動漏れの判定は独立した試験制御の観測で、プラグインに本番監視・メール通知が実装されたことを意味しない。予定した分単位の起動枠を欠かす試験で、日次枠越え・複数日の欠測・監視ホスト自体の停止は別の検証とする。

## 限界と証跡

対象はPHP方式の外部起動経路。native/PHP両方式の自動HTTP起動と隔離復元の過去記録は維持し、今回再実行した件数として合算しない。停止点はDB PUTの応答後で、通信中の結果不明や任意の破壊位置を網羅しない。固定Version ID保持、独立署名、Object Lock、権限分離の受入ではない。

S3生成資産・完了台帳・起動と起動漏れの記録・状態snapshot・ZIPコードハッシュを保存する。成功した試験の専用コンテナと再生成可能なサイト/codeは片付ける。公開、共通化マージ、本番Cron変更は行わない。
