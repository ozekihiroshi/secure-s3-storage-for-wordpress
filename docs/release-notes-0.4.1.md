# 0.4.1 リリースノート（公開前）

独立したDB・メディア保全製品として、既存バックアップを誤って削除しないための
限定的な保持処理の改善。Resilienceとの共通DB部品採用は含まない。

- 新規DBオブジェクトに元gzipのSHA-256をメタデータとして保存。
- 世代削除前に、残す全世代のサイズ・S3 checksum・元digestを照合。
  証拠不足、不一致、HEAD拒否では削除を止め、バックアップの成功とcleanup失敗を分離する。
- 実際に生成する旧/new DBキー形式に削除対象を限定。
- S3一覧の不完全なページング、token循環、重複keyでは削除計画を中止。
- READMEを製品説明中心に整理し、公開版・Recovery Setの保証範囲を明確化。
  過去の設計・試験記録は保存。

## 更新時の注意

0.4.0以前の保持世代には新しいdigestメタデータがない。
新しい照合可能なバックアップがkeep数に達するまで、世代削除が延期される場合がある。
この間は指定世代数を超えて保存されるため、S3容量と履歴のretention警告を確認する。
既存S3オブジェクトやWordPressの設定・履歴を移行する処理は追加しない。

保持枠K件のHEAD/checksum読取りが追加される。必要なS3権限は従来の整合性確認と同じだが、
現在のバックアップだけでなく保持対象にも適用する。メタデータのない旧バックアップを
手動で「検証済み」に書き換える必要はない。

管理画面からの手動DBバックアップは従来どおり自動retentionを実行しない。
Recovery Set、メディアのS3保存領域はこのDB世代管理の対象外。
全サイト復旧、DB/mediaの同時点snapshot、Object Lockや独立署名は提供しない。
