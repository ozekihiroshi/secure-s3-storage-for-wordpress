# 0.4.0 開発候補

公開済み0.3.0とは別の独立改善版。共通DB部品の採用変更は含めない。WordPress.org、GitHub Releaseへの0.4.0公開は未実施。

追加内容：Recovery Setのstatus/latest/observationsとJSON、管理画面、実行記録、予定判定と明示的設定保存、開発者用Cron入口、観測登録、workspace cleanupのdry-runと明示実行。

予定判定の停止・再開は実Cronを変更しない。Recovery Set取得は開発者の明示接続が必要で、一般向け復元UI/CLIは未提供。侵害耐性、独立署名、Object Lockは本製品の保証範囲ではない。

## 版番号と過去試験

プラグインヘッダー、Stable tag、同梱変更履歴を0.4.0へ統一した。コード内の別の製品バージョン定数はない。従来の開発ZIPは誤って公開済みと同じ0.3.0を使っていたため、履歴・証拠のファイル名とハッシュは変更せず維持する。

直前の実S3往復試験はSHA-256 `4a92b0e4ff85f16b34254f41ba54ea626ccaf050f82fd77930e0d6d8b4b80797`の旧番号候補で実施した。0.4.0の新ZIPで実S3を再実行したとは扱わない。今回の変更は版番号・説明と更新試験ツールの版指定のみ。src/vendorの比較と、新ZIPによる公開版0.3.0からの更新・状態保持を別記録に残す。

公開済み0.3.0のGitHubタグ・Releaseは、公開用ソース `627e47c2b31527ef1486e582b79fd5dba875843f`に追加し、WordPress.orgの実配布ZIPをそのまま添付した。既存タグ、公開版ZIP、共通部品ブランチは変更していない。

0.4.0候補ZIPは`build/ozeki-database-backup-for-s3-0.4.0.zip`、SHA-256 `e2a5f0272a0e4b77e86add61775d9529659f0edff00cc44cf5dc170c3c094d57`。[更新検証の機械可読記録](release-0.4.0-validation.json)で対象物を固定する。

専用WordPressで公開0.3.0 ZIPからの更新、0.4.0再適用、無効化・再有効化が合格。設定・実行記録・観測・cleanup台帳・workspaceの保持、管理画面描画とJSON、インストール全ファイルとZIPの一致を確認した。更新時のCron登録は保持され、無効化・再有効化では既存仕様に従って日次イベントが1件再登録される。試験用リソースは削除済み。0.4.0の実S3再試験・新規導入の再試験は今回追加せず、前回の検証と製品実装の一致を明記する。
